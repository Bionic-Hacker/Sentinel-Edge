# v0.4.0 — Phase 7: Security operations

Everything here runs locally; no AWS resources exist yet ([ADR-0016](../adr/0016-local-first-phase-order.md)).
The attack simulator and its WAF are the first implemented **SIMULATED** capabilities, labelled
as such on every record, API view and page.

## What's new
- **Security events:** one append-only record of every security-relevant observation: failed and
  suspicious sign-ins, refresh-token replay, authorization denials (BOLA/BFLA), rate-limit trips,
  attack patterns in requests, and detections. The app's database role cannot change or remove
  them. ([ADR-0018](../adr/0018-security-event-pipeline-and-incidents.md))
- **HTTP attack analysis (detect-only):** 17 rules for SQL injection, XSS, path traversal, command
  injection, SSRF, scanners and reconnaissance on every request, after double percent-decoding.
  Linear-time patterns (an adversarial timing test proves it), bounded input, sensitive fields
  redacted. A pattern in a request that was served is raised a severity level.
- **Correlation rules COR-001 to COR-007:** credential stuffing, sustained password guessing,
  injection campaigns, authorization probing, API abuse, scanning, and a sign-in from a stuffing
  source. They run in the same transaction as the event, under the audit chain's lock, so every
  detection is raised exactly once (30-thread test) and never across live and simulated data.
- **Incidents:** DETECTED → TRIAGED → INVESTIGATING → CONTAINMENT → REMEDIATION → VALIDATION →
  CLOSED, opened automatically for high-severity detections, token theft, suspicious sign-ins and
  audit tampering, or by hand. One open incident per source gathers related activity. Role rules
  are enforced on the server and sent to the UI as the moves each person may make. Evidence links
  are write-once, the timeline is append-only, and each entry's digest is committed to the audit
  chain and verified on every read. Concurrent edits are refused rather than overwritten.
- **Security dashboard:** status line, open incidents, detections, events per hour, threats by
  category, top sources, API traffic and controls, in a **live** view and a **simulated** view
  that are never combined.
- **Threats and Incidents pages:** filters kept in the URL, event detail with the HTTP analysis
  and what matched, incident detail with workflow, evidence, timeline, risk score and integrity.
- **Application inventory:** SentinelEdge is the first registered application; others can be
  registered with owner, environment, criticality and domain. Developers see only their own.
  Measures that need a later phase say so instead of showing a number.
- **Attack simulator (SIMULATED):** 11 scenarios built in memory, with no network traffic and no
  target input, using documentation-range addresses (RFC 5737). Leads run them; every run is
  audited. ([ADR-0019](../adr/0019-attack-simulator-and-simulated-waf.md))
- **Simulated WAF (SIMULATED):** each detection rule can be set to block, count or off with AWS
  WAF semantics. Switching the SQL injection rules to count shows the same payloads reaching the
  application and being detected there. Real WAF rules still change only through Terraform
  (ADR-0008, Phase 5).
- **Runbooks:** credential stuffing, SQL injection event, API abuse, bot traffic. New
  [incident response](../incident-response.md) guide.

## Fixes and improvements
- On a phone-width screen, tables with screen-reader-only labels (Audit Logs, API Security,
  WAF) no longer make the whole page scroll sideways.
- Frontend tests: about 60 s → 12 s, with no `act()` warnings.
- `make smoke` now covers security operations (48 checks, up from 34).

## Evidence
- 668 backend tests (98.6% coverage) against real PostgreSQL, up from 391; 75 frontend tests.
- `make smoke`: 48 end-to-end checks, including a live SQL injection probe recorded through the
  edge, the simulated WAF in block and in count mode, the live and simulated dashboards, and the
  audit chain intact afterwards.
- Every page checked in headless Chromium at 1440 and 390 px wide.
- Ruff, mypy (strict), Bandit, ESLint, TypeScript, schema-drift check, Gitleaks, pip-audit,
  npm audit: clean.
- Threat model v0.4 with nine new security-operations threats (T-SO-01 to T-SO-09); controls
  C-SO-01 to C-SO-09 with their evidence.

## Upgrading from v0.3.0
Your data is kept; `make dev` applies migrations 0006 to 0008. Expect one live incident from your
own testing: `make smoke` replays a token and probes on purpose, and on one machine all of it
comes from one address. See [local-development.md](../local-development.md#upgrading-from-v030-phase-6-to-v040-phase-7).

```
make dev
make smoke
```
