# v0.7.0 — Phase 9: AI security engine

Everything here runs locally. No AWS resources exist ([ADR-0016](../adr/0016-local-first-phase-order.md)).
The engine is off by default. The free `offline` analyser runs it end to end, and Amazon Bedrock
is called only when you switch it on ([setup](../bedrock-setup.md)).

## What's new
- **Analyze with AI** on security events, incidents, findings and threat models. The AI explains
  what happened, classifies it, rates it and recommends controls from the catalogue.
  ([ADR-0024](../adr/0024-ai-security-engine.md), [reference](../ai-security.md))
- **Guardrails on what the model sees.**
  - There is no prompt box: you choose a record, and only an allow-listed, bounded set of its
    fields is sent.
  - Addresses and e-mails are pseudonymised, and invisible characters are removed.
  - The data travels as JSON under a per-call nonce it cannot close.
  - The input is scored for prompt-injection signals (instruction overrides, role markers,
    delimiter spoofing, output steering...), and the signals are shown with the answer.
- **A contract on what the model returns.**
  - One strict JSON object.
  - Every piece of "observed evidence" must quote the data verbatim, and is checked.
  - The model's interpretation is labelled as inference, not fact.
  - Only catalogue control IDs and allowed actions are accepted.
  - Anything else is **rejected, not repaired**, and the page says why.
- **The AI cannot act.**
  - It may propose three actions, all of which tighten: open an incident from an event, set a
    simulated WAF rule back to block, or add a threat to an application's model.
  - An admin or security engineer approves or rejects each one. Approval runs the action as that
    person, through its normal workflow, in one transaction.
  - A WAF change request still needs a second lead.
  - A proposal from a high-risk input needs a written reason to approve.
- **AI Security page:**
  - provider, model and provenance;
  - usage against the daily limits;
  - proposals awaiting a decision;
  - recent analyses with their prompt-risk level.

  Each analysis has its own page: evidence beside inference, any disagreement with the platform's
  own verdict (shown, never acted on), and its proposals.
- **Cost bounds checked before every call:** 20 analyses per user per day, 200,000 tokens per day
  for the platform, and 800 tokens per answer. Every call is audited with its model, usage,
  prompt-risk score and the SHA-256 of the exact prompt.
- **Viewers cannot run analyses**, so the authenticated DAST scan can never spend tokens.
- **Amazon Bedrock provider:**
  - Nova Micro by default, configurable; temperature 0 and timeouts.
  - AWS error text is kept out of responses.
  - `make bedrock-credentials` writes a short-lived session for the local API.
  - The IAM policy in [bedrock-setup.md](../bedrock-setup.md) allows one permission on one model.
- **`make ai-check`** sends one synthetic event, with an injection attempt in its user agent, through
  the configured provider and the contract.
- **Runbook:** [AI prompt injection](../runbooks/ai-prompt-injection.md).

## Fixes and improvements
- nginx gives only `POST /api/v1/ai/analyses` a longer read timeout (75 s), so a real model's answer
  is not cut off at the edge.
- The SPA validates every AI response, including refusing any action the contract does not allow.

## Evidence
- 991 backend tests (98.0% coverage) against real PostgreSQL, up from 892; 115 frontend
  tests, up from 103.
- An injection corpus, hostile and malformed answers, and a deliberately compromised "model" that
  obeys every instruction it is given: each answer is rejected or reduced to a reviewable proposal.
- `make smoke`: 69 checks, up from 64. They pass with AI off and with the offline provider.
- The AI pages checked in headless Chromium at 1440 and 390 px wide.
- Threat model v0.7: T-AI-01 to T-AI-06 mitigated, T-AI-07 to T-AI-10 added, asset A16. Controls
  C-AI-01 to C-AI-07 implemented.

## Known limitations
- Prompt-risk scoring is a set of patterns: it informs the reviewer and can be evaded. The
  defences do not depend on it.
- The offline analyser is not a model. It proves the engine, not the quality of a model's answers.
- Limits are daily, counted from stored analyses.
- A real model can still be wrong within the contract. Inference is labelled, and nothing runs
  without a lead.

## Upgrading from v0.6.0
Your data is kept; `make dev` applies migration 0014. AI stays off until you set
`SENTINEL_AI_PROVIDER`. See
[local-development.md](../local-development.md#upgrading-from-v060-phase-10-to-v070-phase-9).

```
make install
make dev
make check
make smoke
```
