# v0.10.1 — Light and dark themes

SentinelEdge now opens in a light theme: white space, dark text and one deep-cyan accent. The
original dark operations theme stays as an option. A toggle beside the signed-in user's name, at
the top of every page, switches between them.

## What's new
- **Light theme by default**, for every user until they choose otherwise. The sign-in page is
  always light.
- **Dark theme on request:** the platform's original palette, unchanged.
- **Saved with the account, not the browser.** The choice is stored on the user
  (`PUT /api/v1/auth/me/theme`, migration `0017`), so it follows them to any browser or device.
  Web storage stays banned in the web app (ADR-0003); the lint and Semgrep rules are unchanged.
- **Same meaning in both themes.** Each theme has its own provenance colours (Real AWS, Local,
  Simulated, Demo), and every text and background pair meets WCAG 2.2 AA contrast in both,
  including text on its own tinted background.

## Security
- The endpoint changes only the caller's own record and accepts exactly `light` or `dark`;
  anything else, or any extra field, is refused (422). It is a display setting: it grants
  nothing, is never read for an access decision, and is not audited.
- Any signed-in user may call it, including during forced setup, under the `session` rate limit
  (60 a minute per user). The endpoint inventory, the authorization matrix and its sweep cover
  it: 89 endpoints.

## Tests
- Backend: the theme is saved and returned, defaults to light, changes only the caller's own
  record, refuses other values and extra fields, refuses anonymous calls, and is not audited.
- Frontend: the toggle shows the saved theme, switches at once, saves through the API (never
  `localStorage`), and switches back with a message if saving fails.

## Upgrading from v0.10.0
`make migrate` (`0016 -> 0017`) and rebuild the web image (`make dev`). In AWS the change ships
with the next deploy window's images and `make spa-push`; there is no Terraform change.
