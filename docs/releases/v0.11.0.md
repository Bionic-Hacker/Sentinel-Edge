# v0.11.0 — Phase 11: automation and the gated pipeline

CI checks everything that needs no AWS credential, on every push and pull request. Deployment is
a gated command on the owner's machine that refuses any commit that is not the tip of `main` with
every CI check green ([ADR-0030](../adr/0030-ci-never-touches-aws.md),
[devsecops.md](../devsecops.md)). No AWS credential exists in GitHub, by design: the account
denies the OIDC provider the original plan used.

## What's new
- **Gated deploy:** `make deploy-check` (main, clean, equal to `origin/main`, every GitHub check
  run for the commit green; none, pending or failed refuses), `make deploy` (images by digest, a
  saved plan to read), `make deploy-finish` (apply, migrations, SPA, then `edge-check` and the
  audit anchor), `make deploy-verify`.
- **Credentials that last the apply:** Terraform renews its `aws login` credentials through a
  temporary `credential_process` profile; long applies no longer end in `ExpiredToken`.
- **`edge-check` on filtering networks:** when the local resolver hides private DNS answers, the
  private-origin check asks DNS-over-HTTPS, and it can no longer pass on an empty lookup.
- **Configurable gate:** `SCAN_BLOCK_AT=critical|high|medium` (high by default); a non-default
  threshold is printed on every run.
- **Reports:** `make report KIND=security|waf|vulnerabilities|api-inventory|posture|certificates`,
  text or JSON, read-only, live and simulated never mixed.
- **Since v0.10.0:** light and dark themes saved per user (v0.10.1), and CI fixes found at the
  Phase 4–5 pull requests (Gitleaks fixture allowlist, the dbadmin image's Checkov exception,
  Terraform validation of modules that take provider aliases).

## Security
- T-CICD-01 (stolen long-lived cloud keys from CI) mitigated: no key exists. C-IAM-02 implemented.
  Threat model v0.14. The one planned control left is C-CICD-12, a ZAP scan of the live edge, in
  the Phase 12 window.

## Evidence
- 1,068 backend tests (97.5%), 125 frontend tests; Checkov, Gitleaks and Semgrep clean.
- The second deploy window (13–14 October 2026) ran v0.10.1 behind CloudFront and WAF and was
  destroyed (93 resources); its credential and DNS findings are fixed here.
