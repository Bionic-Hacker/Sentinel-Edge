# v0.3.0 — Phase 6: API security

Everything here runs locally; no AWS resources exist yet ([ADR-0016](../adr/0016-local-first-phase-order.md)).

## What's new
- **Rate limiting (OWASP API4, API6):** PostgreSQL token buckets checked by one atomic statement.
  Per-IP limits apply before authentication (sign-in, MFA, refresh, recovery, probes, plus a
  global ceiling); per-account limits apply after it and follow the user across IPs. Throttled
  requests get `429` with `Retry-After`; others carry `RateLimit-*` headers. The first denial in
  a run is audited as `ratelimit.exceeded`. Cannot be disabled when deployed.
  ([ADR-0017](../adr/0017-rate-limiting-and-client-ip.md))
- **API Security Center (`/apis`):** every endpoint with authentication, authorization, risk,
  rate limit, 24-hour requests, error rate, security rejections, last scan and status, generated
  from the live route table. Includes OWASP API Security Top 10 (2023) coverage with the tests
  that prove it. Available to admins, security engineers and developers.
- **Endpoint metrics:** hourly counters per route template, with no IPs, IDs or payloads stored.
  Requests to unknown paths are counted as probing.
- **Trusted client IPs (T-ORG-02):** `X-Forwarded-For` is honoured only from the proxy network.
  nginx overwrites it with the real peer. Audit records now show real client addresses.
- **SSRF guard:** ready for future outbound calls (HTTPS, allow-list, public addresses only,
  including mapped and 6to4 forms of the metadata address).
- **Sweeps:** every request body forbids unknown fields, every JSON route declares a response
  model, and sensitive-looking response fields need explicit approval.
- **Developer experience:** `make dev` explains a failed start (for example, a stale database
  volume) and prints the fix. `make prune-rate-limits` added. Test output no longer has React
  `act()` or Alembic warnings.
- **Phase 2 follow-up:** admins can permanently delete users behind a confirmation dialog. The
  database-port hardening check now works on Docker Compose v5.

## Fixes
- Authorization-denial audit records named router-relative paths (`PATCH /{user_id}`); they now
  record the full endpoint (`PATCH /api/v1/users/{user_id}`).

## Evidence
- 390 backend tests (99% coverage) against real PostgreSQL; 45 frontend tests.
- `make smoke`: 34 end-to-end checks, including a real rate-limit trip, a spoofed
  `X-Forwarded-For` that is ignored, and the inventory counting the throttled requests.
- Verified in headless Chromium against a live API, PostgreSQL and nginx; nothing in web storage.
- Ruff, mypy (strict), Bandit, ESLint, TypeScript, schema-drift check: clean.

## Upgrading from v0.2.0
Your data is kept. Recreate the containers and networks once, because the edge network is now
pinned:

```
docker compose down
make dev
```
