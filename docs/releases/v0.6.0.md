# v0.6.0 — Phase 10: Threat modeling and governance

Everything here runs locally; no AWS resources exist yet ([ADR-0016](../adr/0016-local-first-phase-order.md)).
Governance records are **LOCAL**. A `waf_rule` change request drives only the **SIMULATED** WAF.

## What's new
- **Threat Modeling page.** SentinelEdge's own threat model is in the application, loaded from
  the reviewed `docs/threat-model.md`, with its assets, trust boundaries, data flows, 80 threats,
  attack paths and residual risks, each threat linked to its controls. It is read-only there,
  because it changes through pull requests. ([ADR-0022](../adr/0022-threat-modeling-catalogue-and-posture.md))
- **Models for other applications**, with STRIDE or PASTA (PASTA records its seven stages):
  * Leads build the model: assets, boundaries, flows and threats that must cite real controls.
  * Elements are retired, never deleted.
  * Developers read the models of their own applications.
- **Removing a model:** Delete opens a dialog with two choices.
  * **Archive:** leads, and developers on their own applications. The model is kept and hidden
    from the list by default.
  * **Delete permanently:** leads only. The audit log keeps a summary of what was removed.
  * Analysts and viewers cannot remove anything, and SentinelEdge's own model cannot be removed.
- **Compliance page:**
  * **Posture:** a score for each of 11 categories. Each score starts from control coverage, and
    every deduction names the records behind it. The method is shown with the score, and daily
    snapshots form a trend.
  * **Controls:** all 101 controls, implemented and planned, with their implementation, evidence and the threats they
    mitigate.
  * **Requirements:** requirement → threat → control → evidence.
  * **Exceptions** and **Changes.**
- **Security exceptions** (EXC-n) and **change requests** (CHG-n). Whoever asks cannot approve:
  the service refuses it, and so does the database. Other rules:
  * Exceptions expire no later than their risk allows (critical 30 days, high 90, medium 180,
    low 365).
  * Changes carry a rollback plan and a validation plan, and are implemented with a reference,
    then validated or rolled back.
  * Decisions are final, and each record's history comes from the audit log.
  ([ADR-0023](../adr/0023-exceptions-change-management-separation-of-duties.md))
- **The application is the system of record for accepted risks.** EXC-0001 and EXC-0002 moved
  from the Markdown register into the app. `make accepted-risks` generates the scan gate's
  `scanning/accepted-findings.toml` from approved scan-finding exceptions.
- **Catalogue as code:** `make governance-catalogue` regenerates the catalogue from the two
  documents. CI fails if the documents and the shipped catalogue disagree, or if they cite a
  test that does not exist.
- **Runbook:** [governance](../runbooks/governance.md).

## Fixes and improvements
- React and the router load as their own chunk; the application chunk went from 538 kB to
  about 280 kB.
- Control text no longer shows Markdown code markers.

## Evidence
- 892 backend tests (98.3% coverage) against real PostgreSQL, up from 765; 103
  frontend tests, up from 91.
- `make smoke`: 64 end-to-end checks, up from 56, including:
  * an exception refused for self-approval, then withdrawn;
  * a change request refused for self-approval, then cancelled;
  * a viewer refused an exception request.
- Every new page checked in headless Chromium at 1440 and 390 px wide.
- Threat model v0.6 with assets A14 and A15, flow F10 and nine new threats (T-GOV-01 to
  T-GOV-09).
- Controls C-GOV-03 and C-GOV-06 to C-GOV-10 are new, and C-GOV-04, C-API-01 and C-API-13 are
  extended.

## Known limitations
- Separation of duties needs two lead accounts; on this single-maintainer project both belong
  to the same person.
- The accepted-risk file is generated on demand. Run `make accepted-risks` after a scan-finding
  decision and commit it.
- Expiry and daily snapshots run on reads and writes, not on a schedule. A scheduler arrives
  with the AWS phases.
- An archived model has no unarchive button yet. A lead can restore it through the API.
