# v0.8.0 — Phase 3: AWS foundation

The first real AWS resources, all as Terraform, in the project's own account (us-east-2). Nothing
that serves traffic is deployed yet: the workload (Phase 4) and the edge (Phase 5) arrive in one
short deploy window. While idle, everything here costs about $2 a month (two KMS keys), paid from
the account's sign-up credits ([ADR-0025](../adr/0025-aws-account-domain-and-deploy-window.md)).

## What's new
- **Three Terraform stacks** ([terraform/README.md](../../terraform/README.md),
  [setup](../aws-setup.md)):
  - `bootstrap`: the remote-state bucket (SSE-KMS under its own key, writes under any other key
    denied, versioned, TLS-only, access-logged, `prevent_destroy`), an access-log bucket, and a
    $30 monthly budget with alerts at $5, $15 and $30 plus a forecast alert;
  - `account`: S3 public access blocked account-wide, EBS encryption by default, a multi-region
    CloudTrail trail (digest validation, KMS, CloudWatch Logs), four CIS security alarms to an
    encrypted topic (root use, trail changes, keys disabled or deleted, bursts of access-denied
    calls), the platform KMS key, and a one-model Bedrock role for the local API;
  - `dev`: a VPC across two zones pinned by ID, with public, app and isolated data subnets (the
    data tier has no route out), flow logs, a free S3 endpoint, the ALB → app → database
    security-group chain, an ECR repository (immutable tags, scan on push, KMS), and certificates
    for `app.sentineledge.is-a.dev` in us-east-1 (CloudFront) and us-east-2 (the internal ALB).
- **NAT is a switch** (`nat_mode`): `none` between windows (nothing hourly), `instance` (a t4g.nano
  NAT instance: IMDSv2, encrypted, no SSH, no role) or `gateway`.
- **Guarded runs:** `make tf-plan` saves a plan and `make tf-apply` applies only that plan; both
  refuse another account and the root user. No access key exists anywhere: you sign in with
  `aws login`.
- **Tested and scanned before applying:** `make tf-check` runs fmt, validate, module tests with a
  mocked AWS provider (no credentials, no cost), and TFLint; Checkov scans Terraform in the scan
  gate. CI gains a Terraform job.
- **A free domain:** `scripts/isadev-records.py` writes the is-a.dev pull request for the name:
  CAA allowing only Amazon and no wildcards, plus the certificate's validation record, which never
  changes.
- **Bedrock without keys:** `make bedrock-credentials` turns an `aws login` session into a one-hour
  session of the one-model role; the signed-in session never enters a container. The default model
  becomes `us.amazon.nova-micro-v1:0`, the US inference profile, which is how us-east-2 offers it.
- **Runbook:** [AWS cost runaway, or a deploy window left running](../runbooks/aws-cost-runaway.md).

## What the account does not allow
The account comes from AWS's newer sign-up experience. Its AWS-written guardrails deny IAM Access
Analyzer and OIDC identity providers, so neither is created; Phase 11 revisits CI's route into AWS
([ADR-0010 addendum](../adr/0010-cicd-oidc-and-pinning.md)). The home Region (us-east-2) is fixed;
us-east-1 is used only for what CloudFront requires there.

## Evidence
- Applied: bootstrap 18 resources, account 27; a re-plan of the account shows no changes.
- 991 backend tests (98.0% coverage) and 115 frontend tests; 8 Terraform module tests.
- Checkov: no failures across the Terraform, with every exception written in place with its reason.
- Threat model v0.8: T-IAC-01 and T-IAC-02 mitigated; T-IAC-03, T-IAC-04, T-AWS-01 to T-AWS-03,
  T-COST-01 and T-DNS-01 added; asset A17. Controls C-IAC-01 to C-IAC-04, C-NET-01, C-NET-02,
  C-NET-04, C-AWS-01, C-LOG-04, C-MON-02, C-COST-01, C-IAM-01 and C-IAM-03 implemented.

## Known limitations
- No keyless route from GitHub Actions into the account: Terraform runs from the owner's machine.
- One NAT for both zones in dev.
- The DNS name lives in a zone run by volunteers (is-a.dev); CAA limits who may issue for it.
- The certificates stay pending until the is-a.dev pull request is merged.

## Upgrading from v0.7.0
Nothing changes in the local stack. In `.env`, set `SENTINEL_AWS_REGION=us-east-2` and
`SENTINEL_AI_MODEL=us.amazon.nova-micro-v1:0` if they still say us-east-1 and the bare model ID. To work with the AWS stacks, install the tools and sign in
([aws-setup.md](../aws-setup.md)):

```
sudo pacman -S --needed aws-cli-v2 terraform
make check
make tf-check
```
