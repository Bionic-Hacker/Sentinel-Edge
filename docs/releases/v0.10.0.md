# v0.10.0 — Phase 5: the edge

SentinelEdge in AWS is reached only through its own edge: CloudFront for
`sentineledge.bionichacker.dev` with AWS WAF in front, a private VPC origin to the internal load
balancer, the web app from a private S3 bucket, and the same security headers as locally. The
dashboard reads the edge back: real WAF blocks become security events and both ACM certificates are
monitored. Phases 4 and 5 were applied together in one deploy window on 12–13 October 2026, proven
from the internet, and destroyed again ([ADR-0027](../adr/0027-cloudfront-waf-and-the-private-origin.md),
[ADR-0029](../adr/0029-the-edge-read-back.md)).

This is the version to deploy; it includes every fix the window needed.

## What's new
- **CloudFront** ([cdn-security.md](../cdn-security.md)): TLS 1.2 or later (`TLSv1.2_2021`),
  HTTP/2 and HTTP/3, HTTP redirected for pages and refused for the API. `/api/*` goes through a
  **VPC origin** to the internal ALB (never cached, Host forwarded); everything else comes from a
  private S3 bucket through Origin Access Control, with a CloudFront Function serving client-side
  routes. The response-headers policy is identical to the local nginx's, by test.
- **AWS WAF** ([waf.md](../waf.md)): IP reputation, the core rule set, known bad inputs (Log4j),
  SQL injection, a 64 KB body cap, and rate rules per IP (sign-in 100, API 2000 per 5 minutes);
  logged with credentials redacted; changed only through Terraform.
- **The edge read back** (ADR-0029): every five minutes the API reads new WAF blocks into
  **Real AWS** security events (deduplicated, correlated) on the WAF and Threats pages, with
  **Sync now** for leads. A new **Certificates** page lists both ACM certificates live, and an
  expiring, failed or unrenewed certificate raises an event
  ([certificate-management.md](../certificate-management.md)). The API's role can only read.
- **Route 53 query logging**: every DNS query for the platform's name, kept a year (completes the
  Phase 3 DNS work).
- **No email path** ([ADR-0028](../adr/0028-account-recovery-through-an-administrator.md)): an
  administrator creates users and resets forgotten passwords, and is shown a generated temporary
  password once (72 hours, hashed, never logged, replaced at first sign-in). The forgot-password
  and reset-link flows, the local outbox and `make outbox` are gone.
- **The first administrator in AWS**: `make ecs-task TASK=create-admin EMAIL=…` writes the
  one-time password to Secrets Manager, never to a log.
- **Tooling:** `make spa-push` (publish the web app), `make edge-check` (21 checks from the
  internet).
- **Honest labels:** the banner asks the API where it runs; the dashboard counts real edge blocks;
  the Edge, WAF and Certificates capabilities are Real AWS.
- Settings: an administrator's Change password and Users panels open on demand.

## Evidence (deploy window, 12–13 October 2026)
- `make edge-check`: **all 21 checks passed**: redirect, TLS, nine headers identical to local,
  client-side routes, API ready with its own CSP and HSTS, an SQL injection and a Log4j probe
  blocked by WAF, the ALB private and unreachable, no API under the distribution's own name.
- 198 WAF blocks read back in 24 hours, 179 of them internet scanners probing exploitable paths
  within hours of the name going live; correlation saw them like any other event.
- Both certificates read live (us-east-1 and us-east-2), ISSUED, renewing automatically.
- Sign-in as the administrator created through Secrets Manager, with MFA; a user created and a
  password reset with temporary passwords.
- A re-plan after the fixes showed `No changes`; switching off destroyed 93 resources.
- 1,036 backend tests (97.3%), 121 frontend tests, Terraform module tests (waf, edge, ecs,
  dns-query-logs and the rest), Checkov with no failures.
- Threat model v0.13: T-EDGE-01 to T-EDGE-11, T-WAF-01/02, T-SEC-03, T-ID-11/12 mitigated;
  T-API-04, T-API-07, T-ID-01 and T-DNS-01 completed at the edge. Controls C-EDGE-01 to C-EDGE-06,
  C-WAF-01 to C-WAF-04 and C-DNS-02 implemented.

## What the window found, and fixed
- The Free plan's service control policy denies S3 buckets in us-east-1 (the SPA bucket moved to
  the home Region) and launches only Free Tier instance types (NAT on `t4g.micro`).
- Task definitions and the RDS parameter group are written exactly as AWS returns them, so a
  plan settles at `No changes`.
- Health checks address tasks by IP; only `GET /api/v1/health` skips the Host allow-list.
- Invitation links had no way to reach anyone in AWS: replaced by ADR-0028.
- Certificate monitoring and WAF log ingestion, planned for Phase 5, were built in the window.

## Known limitations
- WAF Bot Control and CAPTCHA are not adopted (cost); sign-in relies on rate rules, lockout and MFA.
- A ZAP scan of the live edge moves to the Phase 12 deploy window; `make edge-check` is this
  release's live evidence.
- No geographic restriction or origin failover; no DNSSEC (the registrar cannot hold the DS record).
- WAF blocks reach the dashboard up to five minutes late.

## Upgrading from v0.9.0
Locally: `make migrate` applies `0015` (drops the outbox and reset-link tables) and `0016` (a
unique index for events read from AWS). Users who had an unused invitation link need an
administrator to **Reset password** for them. `make outbox` no longer exists. See
[local-development.md](../local-development.md#upgrading-from-v090-phase-4-to-v0100-phase-5).

In AWS: apply the dev stack once for Route 53 query logging (no window needed), then follow
[aws-deploy-window.md](../aws-deploy-window.md).
