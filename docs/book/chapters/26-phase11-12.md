# Phases 11–12 — Automation and Final Hardening

<p class="lead">The last two phases join everything into one gated pipeline and then review the whole system as an assessor would. <span class="status plan">Planned</span></p>

## Phase 11 — Automation and DevSecOps

The full pipeline: commit → unit tests → lint → SAST → SCA → secret scan → IaC scan → SBOM → container build → container scan → push to ECR → Terraform validate → Terraform plan → deployment → DAST → post-deployment security validation. Thresholds for critical and high findings are configurable, and the pipeline fails on them.

CI reaches AWS through **GitHub OIDC** (ADR-0010). There are no long-lived keys. Trust policies pin `aud` and a `sub` scoped to a GitHub *environment*, and production requires reviewer approval. Python automation tools ship with CLI examples: `security_report.py`, `certificate_inventory.py`, `api_inventory.py`, vulnerability reporting, WAF event analysis and posture calculation.

## Phase 12 — Portfolio hardening

A full security review across dependencies, IAM, Terraform, WAF, API, AI and containers. Final documents are produced: `SECURITY_ASSESSMENT.md`, `ARCHITECTURE.md`, `THREAT_MODEL.md`, `INTERVIEW_DEMO.md` and `LESSONS_LEARNED.md`. Known hardening candidates already recorded include asymmetric JWT keys with rotation (`kid`), the database load of rate-limit and metrics writes, and the remaining runbooks.

## Demo mode

The primary interview demonstration runs end to end. A suspicious request is simulated, the WAF detects and blocks it, a security event appears, an analyst opens it, AI analyzes it, an incident is created and investigated, a remediation is recommended and documented, and the dashboard updates. Five documented scenarios (SQL injection, credential stuffing, API abuse, prompt injection, certificate expiration) each cover attack, detection, control, evidence, investigation, remediation and validation.
