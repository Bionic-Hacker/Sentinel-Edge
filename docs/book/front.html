What it demonstrates

The project sets out to support one sentence in an interview: "I can design, build, secure, automate, deploy, monitor, and govern an internet-facing, AI-enabled application in AWS." It is aimed at Application Security, Product Security, API Security, Cloud Security, DevSecOps, AI Application Security and WAF/CDN Security engineering roles.

  • Secure application engineering: Argon2id passwords, short-lived JWTs checked against a live session on every request, rotating refresh tokens with theft detection, TOTP MFA, CSRF defenses, and no default credentials anywhere.
  • Authorization that cannot drift: five roles, an access rule declared on every route, and a test that sweeps every route as every role and fails if code and policy disagree.
  • Tamper-evident audit: a SHA-256 hash chain, append-only by database grant and trigger, verifiable from the CLI, the API and the UI.
  • API security: atomic PostgreSQL token-bucket rate limiting, spoof-proof client-IP resolution, and a live API inventory generated from the route table. OWASP API Top 10 coverage is mapped, with cited test evidence.
  • Security operations: detect-only attack analysis on every request, correlation rules that fire exactly once, and an incident workflow whose evidence is append-only and whose timeline is committed to the audit chain, so it cannot be rewritten unnoticed. An attack simulator that cannot be pointed at anything, with a simulated WAF that shows block versus count.
  • Application security scanning: SAST with the project's own rules, dependency, secret, IaC and container scanning, SBOMs and authenticated DAST in one pipeline, behind a gate that fails closed; findings tracked to closure with deadlines and expiring, immutable risk acceptances.
  • Governance that cannot drift: the threat model and control catalogue are code, loaded into the application and checked against the documents by a test; a posture score where every point traces to a control or a record; exceptions and changes where whoever asks cannot approve, enforced by the service and the database.
  • Honesty about what is real: every capability is labelled REAL_AWS, LOCAL, SIMULATED or DEMO, and tests stop anything being presented as an AWS control before it is one.
  • Cloud architecture designed ahead of spend: a private-origin AWS design (CloudFront VPC origins, internal ALB, isolated RDS, WAF changes only through Terraform), built late on purpose so no infrastructure sits idle.

How to read this book

Recruiters and hiring managers: this page, Chapter 1 and Chapter 2 tell the story in about ten minutes. Engineers and reviewers: Part I is the blueprint (architecture, stack and security design). Part II walks through each completed phase: what was built, why, how it works and how it is verified. Part III describes the remaining phases as designed. Anyone reproducing the build: Part IV contains the commands, in order, that bring the platform up from an empty machine and verify it.
